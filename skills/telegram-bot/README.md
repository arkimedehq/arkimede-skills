# 💬 Telegram Bot — Arkimede Chat on Telegram

Connects Arkimede to Telegram. Every Arkimede user can link their account
to the bot and chat as if they were using the web interface — with full access
to all the tools, MCP, RAG and skills configured in their profile.

---

## ⚙️ Configuration

### 1. Create the bot on Telegram

1. Open Telegram and search for **@BotFather**
2. Send `/newbot` and follow the instructions (name + username)
3. BotFather will return a **token** in the format `1234567890:AAF...`

### 2. Configure the skill in Arkimede

1. Go to **Settings → Skills → telegram-bot → Configure**
2. Set `TELEGRAM_BOT_TOKEN` with the token obtained from BotFather
3. Go back to the skill and click **Start daemon**

The bot is now listening. Every Arkimede user can link their account
by following the section below.

---

## 🔗 Linking a user account

Each Arkimede user opens the bot on Telegram and sends:

```
/login email@esempio.com latuapassword
```

The bot authenticates the credentials against Arkimede, saves the session and **automatically
deletes the message containing the credentials** for security.

From that moment on, all messages sent to the bot are processed as Arkimede
chats, with access to all the user's tools and settings.

## ✅ Available commands

| Command | Action |
|---------|--------|
| `/start` | Welcome message |
| `/login email password` | Link your Arkimede account |
| `/new` | Start a new conversation |
| `/help` | Show available commands |

## 🤖 How it works

The daemon runs in the background as a long-running process. When a user sends
a text message:

1. The daemon retrieves (or creates) the Arkimede chat associated with the Telegram conversation
2. It sends the message to the backend via SSE streaming (`POST /api/chats/:id/messages/stream`)
3. Once the response text has accumulated, it sends it to Telegram (split into
   4000-character chunks if it exceeds the Telegram limit)
4. If the response contains files (PDFs or other documents generated by the tools), it sends them
   as Telegram attachments automatically

Each Telegram conversation is a separate chat in Arkimede, **also visible
from the web interface**. The `/new` command resets the mapping and forces the creation
of a new chat on the next message.

---

## 📎 Automatic sending of file attachments

The daemon automatically detects files generated by Arkimede tools (PDF, Excel, etc.)
and sends them as Telegram documents attached to the text response.

### How files are found

**Priority 1 — SSE `file` event** (preferred): the backend emits an SSE event
`{ type: "file", absPath: "/path/assoluto/file.pdf", name: "file.pdf" }` during
streaming. The daemon uses the absolute path directly to read the file from disk.

**Priority 2 — Text parsing** (fallback): the daemon analyzes the text response
looking for JSON patterns typical of tool output:
- `"download_url":"skills-output/pdfs/file.pdf"` → resolved against `FILES_BASE_DIR`
- `"file_path":"/path/assoluto/file.pdf"` → used directly if inside `FILES_BASE_DIR`
- `/api/files/raw?rel=…` or `/api/files/:uuid/download` URLs → downloaded via HTTP with JWT

**Telegram file size limit:** 50 MB. Larger files receive a notice
inviting the user to download them from the site.

---

## 👥 Multi-user

A single bot can be shared among multiple Arkimede users. Each user authenticates
independently with `/login` and has their own isolated session — conversations
and tools are always those of their own account.

---

## 🔔 Sessions and DB persistence

Sessions (JWT, email, chat mapping) are saved **in the database as an encrypted config
var** (`TG_SESSIONS`, `secret: true`), **not** in a local file. This
ensures that sessions survive daemon restarts and remain secure.

On restart the daemon re-reads the sessions from `_config.TG_SESSIONS` (injected
automatically by the backend).

The content of `TG_SESSIONS` is managed automatically — do not modify it manually.

---

## 🔄 Automatic token renewal

If the Arkimede JWT expires, the daemon automatically performs a re-login using the
saved credentials. If the re-login fails (password changed, account disabled),
the bot replies with a message inviting the user to repeat `/login`.

## Configuration variables

| Key | Description | Required |
|--------|-------------|:---:|
| `TELEGRAM_BOT_TOKEN` | Telegram bot token (from @BotFather) | ✅ |
| `TG_SESSIONS` | User sessions — managed automatically, do not modify | ❌ |
| `FILES_BASE_DIR` | Base directory for files generated by the tools. Default: system `UPLOAD_DIR` | ❌ |
